# PoC Stage 0～5｜分階段執行及封版門檻

| 階段 | 目的 | 必要證據 | 放行門檻 |
|---|---|---|---|
| Stage 0 | 固定測資、36測試、環境與證據格式 | SHA-256、靜態校驗、工具盤點 | 靜態校驗成功；使用者本機環境另行確認 |
| Stage 1 | 技術中立執行器、回應格式與測試替身 | 單元測試、錯誤代碼範例、固定資料重設 | 不連接雲端也能產生可驗證的測試結果 |
| Stage 2 | Firebase Authentication＋Firestore＋受控寫入 | 權限、交易、衝突、操作收據、失敗注入 | 可在隔離的 emulator／測試環境重播同一契約 |
| Stage 3 | PostgreSQL＋授權／RLS＋交易式提交 | 同一套測資、相同輸入輸出、回滾證據 | 與 Firebase 在語意上可直接比較，不豁免 P0 |
| Stage 4 | 真實 iPad／斷網／切帳／雲端費用及還原 | 真機截圖、操作軌跡、備份復原、成本測量 | 所有 P0 有實機或正式測試環境證據 |
| Stage 5 | ADR 技術選型 | 對照矩陣、P0/P1 與成本、維護風險 | P0=20/20 PASS，P1 風險經正式決議 |

## 測試分組（兩個候選須以同一版本測試矩陣執行）

- **SEC**：身份、工作空間、敏感權限與高權限服務存取。
- **DOMAIN**：歷史在籍、15人點名、SC-01、請假四態與統計未知。
- **TX**：雙裝置版本競爭、100次重送、冪等回覆、交易失敗回滾。
- **SYNC**：核對來源版本過期、投影事件去重及衍生資料延遲。
- **OFFLINE**：本機可靠保存、重啟、切帳隔離與過期版本衝突。
- **DR**：備份實際還原、讀寫量、p50/p95/p99 與月成本推估。

執行次序可先測 P0 再測 P1；**不得為任一候選使用不同的預期條件或放寬 P0**。

## 靜態契約 vs 真實實測

Stage 0 的校驗只確認 CSV/JSON 檔案格式與內容一致，**不會**執行資料庫交易、Security Rules、RLS、離線快取、CI、iPad 真機、備份或計費。所有真實 PoC 都維持 NOT_RUN。
